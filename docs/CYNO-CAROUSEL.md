# Cyno 영화 캐러셀

## 결론

Cyno의 기본 캐러셀은 **별점 목록형과 작품노트형을 합친 5장 구성**으로 운영한다.

1. 표지: 주제, 전체 편수, 대표 포스터 3장
2. 목록: 별점순 영화 1~6
3. 목록: 별점순 영화 7~12
4. 목록: 별점순 영화 13~18
5. 작품노트: 목록 안 한 편의 기존 Cyno 코멘트

사람이 하는 일은 주제를 고르고 저장하는 것뿐이다. 영화 선택, 정렬, 포스터 배치, 초과 편수 표기, 캡션 생성은 데이터에서 자동으로 처리한다.

## 목표와 제약

이 기능의 목표는 멋진 카드 한 세트를 오래 편집하는 것이 아니라, 주 2~3회 발행할 수 있을 만큼 제작 마찰을 낮추는 것이다.

- 대상은 계정 소유자 한 명이다.
- 새 데이터 입력과 AI 문구 생성은 요구하지 않는다.
- 왓챠 별점, TMDB 포스터, 기존 영화 코멘트를 재사용한다.
- 카드 한 장은 Instagram 세로형 `1080×1350`이다.
- 새 npm 패키지, 새 서버 캐시, Gemini 호출, GitHub Contents API 쓰기를 추가하지 않는다.
- 포스터가 실패해도 전체 생성은 계속되어야 한다.
- 모델명, 원문 영화 데이터, `source_hash`는 변경하지 않는다.

## 검토한 세 가지 디자인

| 안 | 장점 | 문제 | 판단 |
|---|---|---|---|
| 작품노트형 | 한 작품을 깊게 읽게 하고 Cyno의 정체성이 강하다 | 매번 문장을 고르고 다듬어야 해 발행 빈도가 다시 떨어질 수 있다 | 단독 기본형으로는 부적합 |
| 별점 목록형 | 기존 데이터만으로 즉시 만들 수 있고 한 게시물에 최대 18편을 소개한다 | 목록만 이어지면 취향 아카이브보다 순위표처럼 보인다 | 자동화의 뼈대로 채택 |
| 혼합형 | 2~4장의 효율과 5장의 개인적 목소리를 함께 유지한다 | 마지막 코멘트가 있는 영화와 왓챠 기록을 정확히 연결해야 한다 | **기본 디자인으로 채택** |

## 시각 시스템

### 공통

- 배경은 포스터가 돋보이는 짙은 중성색을 사용한다.
- 포인트 색은 Cyno의 연보라색 한 가지로 제한한다.
- 본문은 Pretendard 계열, `Cyno.` 서명은 serif 계열을 사용한다.
- 가장자리 안전 여백은 84px로 유지한다.
- 모든 장에 페이지 번호와 5단계 진행 표시를 둔다.
- 작은 장식보다 제목, 별점, 포스터의 대비를 우선한다.

### 1장 — 표지

- 대표 포스터 세 장을 같은 크기로 나란히 놓아 컬렉션임을 즉시 보여준다.
- 주제 문구를 가장 큰 글자로 두고, `별점순 상위 18편`을 보조 문구로 둔다.
- 전체 후보가 18편을 넘으면 `외 N편`을 숨기지 않고 포인트 색으로 표시한다.
- 대표 포스터를 흐린 전체 배경으로 다시 사용해 별도 배경 자산을 만들지 않는다.

### 2~4장 — 영화 목록

- 한 장당 6편, 3×2 배열이다. 3×3보다 포스터 면적이 약 50% 커져 모바일에서도 작품을 구별할 수 있다.
- 포스터 아래에는 `제목`, `연도 · ★별점`만 둔다.
- 제목은 한 줄 안에서 자동 축소하되 읽을 수 없는 크기까지 줄이지 않는다.
- 6편보다 적은 장은 빈 칸을 남기지 않고 1×1, 2×1, 2×2, 3×2처럼 중앙 정렬한다.
- 포스터 로딩 실패는 영화 제목 첫 글자가 있는 중성색 카드로 대체한다.

### 5장 — 작품노트

- 목록에 실제 포함된 영화 중 기존 코멘트가 있는 첫 작품을 사용한다.
- 포스터를 상단과 배경에 활용하고, 아래에는 코멘트가 읽히는 단색 영역을 둔다.
- 코멘트는 최대 영역에 맞춰 글자 크기를 자동 조정한다.
- 영화명, 감독, 연도, 별점과 `@lyra.syno`를 함께 표시한다.
- 새 문장을 생성하지 않는다. 기록이 없는 프리셋은 발행 후보에서 제외한다.

## 제작 화면 UX

진입점은 `/movies` 상단의 `캐러셀 만들기` 버튼이다.

1. 모달을 열면 첫 프리셋의 5장을 자동 생성한다.
2. 오른쪽에서 주제를 바꾸면 포스터를 최대 5개씩 병렬로 읽고 카드를 다시 만든다.
3. 큰 미리보기와 5개 썸네일로 업로드 순서를 확인한다.
4. 모바일에서는 미리보기 높이를 제한하고 화면 폭을 넘지 않게 세로 스크롤한다.
5. `5장 저장`은 모바일 공유 시트를 먼저 사용하고, 지원하지 않으면 `cyno-<주제>-01.png`부터 순차 다운로드한다.
6. 생성된 Instagram 캡션은 별도 버튼으로 복사한다.

## 데이터와 선택 규칙

- 기본 정렬: 별점 내림차순 → 연도 내림차순 → 한글 제목순
- 최대 선택: 18편
- 프리셋: ★5, ★4.5 이상, 2000년대, 한국 영화 상위, 일본 영화 상위
- 전체 후보 수와 실제 수록 수를 분리해 보관한다.
- 잘린 수는 `전체 후보 - 실제 수록`로 계산해 표지와 제작 화면에 표시한다.
- 왓챠 기록과 영화 코멘트는 TMDB ID를 먼저 사용하고, 없으면 정규화한 제목과 연도로 연결한다.

## 발행 운영

권장 순환은 다음과 같다.

1. 넓은 주제: ★5 또는 ★4.5 이상
2. 시대 주제: 2000년대, 이후 다른 연대 프리셋
3. 지역 주제: 한국, 일본, 유럽 등
4. 반응이 좋았던 목록의 한 작품을 별도 작품노트형 게시물로 확장

같은 상위 18편이 반복되지 않도록 후속 개선에서는 이미 발행한 프리셋과 범위를 로컬 운영 기록으로만 관리한다. 이번 릴리스에는 새 저장 구조를 넣지 않는다.

## 배포 방식

GitHub 계정 플래그 때문에 Git push가 Vercel 빌드를 발생시키지 않는다. 따라서 깨끗한 worktree와 Vercel CLI를 사용한다.

### 릴리스 순서

1. 최신 `origin/main`에서 깨끗한 release worktree를 만든다.
2. 캐러셀 변경만 한 커밋으로 통합한다.
3. `pnpm test`, `pnpm lint:data`, `pnpm build`, `pnpm smoke`를 통과시킨다.
4. 로컬 production 서버에서 실제 카드 5장과 모바일 모달을 확인한다.
5. 필요하면 CLI preview를 만들어 원격 자산 로딩을 확인한다.
6. production 승인 후 같은 깨끗한 worktree에서 `pnpm deploy:prod`로 한 번만 업로드한다.
7. 배포 URL과 `/api/version`을 확인하고 `/movies`에서 카드를 다시 생성한다.

### 실패 시 복구

- UI 또는 이미지 생성 회귀는 직전 production deployment로 rollback한다.
- DB migration과 새 환경변수가 없으므로 rollback에 데이터 복구가 필요하지 않다.
- 배포 전에 변경 커밋 SHA와 배포 ID를 기록한다.
- 대시보드 Redeploy는 새 커밋을 가져오지 못하므로 사용하지 않는다.

## 완료 판정

- 모든 프리셋이 정확히 5장을 만든다.
- 카드 PNG는 모두 `1080×1350`이다.
- 18편 초과 수가 화면과 표지에 보인다.
- 포스터 실패가 전체 생성을 중단하지 않는다.
- 모바일 390px에서 모달이 문서 폭을 넓히지 않는다.
- 모델명과 영화 원본 데이터는 바뀌지 않는다.
- 전체 테스트, 데이터 검사, production build와 smoke가 통과한다.
