# 무료티어 장애 런북

무엇이 보이는가 → 무엇이 원인인가 → 무엇을 하는가.

이 사이트는 전부 무료티어로 돈다. 한도를 넘으면 요금이 오르는 게 아니라
**멈춘다** — 그래서 장애의 절반은 "고장"이 아니라 "한도"다. 먼저 그 구분부터 한다.

## 0. 먼저 여기부터

```bash
node scripts/quota-watch.mjs      # 저장소·헬스체크·전송량·캐시·AI 호출 한 판
node scripts/healthcheck.mjs      # 배포가 살아 있는지만
```

`/api/version`이 원천이다. `contentFallback: true`면 DB가 아니라 파일 백업을
읽는 중이고, 관리자 화면 맨 위에 붉은 배너가 떠 있다.

---

## 1. 사이트가 500이거나 관리자에서 저장이 안 된다

**증상** 페이지가 열리긴 하는데 최근 등록한 곡이 없다. 저장을 누르면 실패한다.
배너: "Neon 응답 없음 — 파일 백업에서 읽는 중".

**원인** Neon Free의 월 전송 5GB를 넘겨 compute가 다음 주기까지 멈췄다.
2026-08-22에 실제로 겪었다 — 캐시 시한을 5분으로 줄인 탓에 곡+영화 2.3MB를
하루 288번 다시 읽어 월 20GB를 썼다. 모든 DB 읽기가 HTTP 402를 냈고, 사이트는
캐시로 버텼지만 **빌드가 sitemap을 만들다 죽어 배포가 막혔고 관리자도 열리지
않았다.**

**확인**
```bash
node scripts/quota-watch.mjs      # Neon 월 전송량 줄을 본다
```
Neon 콘솔 → 프로젝트 → Usage. API로 보려면 `NEON_API_KEY`·`NEON_PROJECT_ID`가
있어야 한다(없으면 "실측 불가"로 나온다 — 0GB가 아니다).

**대응**
1. **읽기는 이미 살아 있다.** 파일 폴백이 `songs/*.md`를 읽어 사이트를 띄운다.
   급한 것은 아무것도 없다.
2. **쓰기는 포기한다.** 폴백에 쓰기는 없다. 다음 주기까지 곡 등록을 미룬다.
   지금 쓴 내용은 브라우저 초안으로 남는다(7일) — 다시 열면 복원 안내가 뜬다.
3. 정말 급하면 `LYRA_CONTENT_STORE`를 파일 모드로 두고 `.md`를 직접 고쳐
   배포한다. **그 뒤 반드시** `node scripts/migrate-content.mjs`로 DB에 올린다 —
   안 하면 Neon이 돌아온 순간 그 변경이 사라진다.

**재발 방지** 캐시 시한(`CACHE_TTL_SECONDS`)을 줄이지 않는다. 지금 6시간이라
월 0.6GB다. 즉시 반영이 필요한 저장 경로는 태그 무효화를 부르므로 시한과
무관하다 — 시한은 무효화를 놓친 경로를 위한 그물일 뿐이다.

## 2. Gemini가 계속 429를 낸다

**증상** 곡 등록의 "분석"이 실패한다. 관리자 사용량 화면에 "AI 공급자 할당량이
막혀 오늘 조사를 중단했습니다".

**원인 가리기** 두 가지가 다르다.
- **모델 RPD** — 그 모델의 하루치를 다 썼다. 대체 사슬이 다른 모델로 넘어간다.
- **그라운딩 검색 한도** — 모델은 멀쩡한데 웹 검색이 막혔다. 2026-09-05에 이게
  먼저 소진돼 연구 기능만 죽고 번역은 멀쩡했다(`lib/admin/gemini.js` 주석).

`/admin/usage`의 AI 카드가 어느 쪽인지 말해 준다.

**대응**
1. **등록을 멈추지 않는다.** 곡 등록 화면의 **"AI 보류로 저장"** 으로 Gemini
   없이 저장한다. 번역·키워드·감정이 빈 채로 들어가고, 공개 페이지는 원문만
   보여준다(빈 번역 칸은 그리지 않는다).
2. 비워 둔 항목은 `needs.js`가 결손으로 잡아 관리자 대기열에 올린다. 예산이
   리셋되면(KST 자정) 거기서 한 곡씩 채운다.
3. 재시도하지 않는다. 5xx·무응답은 모델 전체가 막힌 것이고, 재시도는 한도만
   더 태운다. 이 정책을 되돌리지 말 것.

**전곡 조사가 중간에 멈췄다면** `/admin/usage`가 남은 곡 수와 재개 가능 여부를
알려준다. 예산이 있으면 `pnpm appearances:resume` — 체크포인트 이후부터
이어가고 끝난 곡은 건너뛴다. **서버에서 돌리지 않는다**: 수백 번의 호출이라
서버리스 함수에서는 실행 시간과 예산이 함께 터진다.

## 3. 파일 폴백으로 도는 중이다

**증상** 배너가 떠 있는데 사이트는 멀쩡해 보인다.

**알아야 할 것** 보이는 데이터가 **최신이 아니다.** 폴백은 배포 번들에 실린
`songs/*.md`를 읽는다 — 마지막 백업 시점의 상태다.

**대응**
1. Neon이 돌아왔는지 `node scripts/healthcheck.mjs`로 확인한다.
2. 폴백 중에 `.md`를 고쳤다면 `node scripts/migrate-content.mjs`로 DB에 올린다.
   고치지 않았다면 아무것도 하지 않는다 — DB가 원천이고 파일은 백업이다.
3. 반대 방향(DB → 파일)은 `node scripts/dump-content.mjs`. `--check`로 차이만
   먼저 본다.

---

## 4. 백업이 실패했다

**증상** Actions에서 `database backup`이 빨갛다. 또는 "백업 무결성 경보" 이슈.

**원인 가리기**
- **무결성 검사가 막은 것** — 덤프가 전날보다 20% 넘게 줄었다. 이건 검사가
  제 일을 한 것이다. **어제 백업은 그대로 살아 있다.**
- **덤프 자체가 실패** — `DATABASE_URL` 문제이거나 Neon이 멈춰 있다.

**대응**
1. 워크플로 요약의 무결성 리포트를 읽는다 — 곡·영화가 이전/이번 몇 개인지 나온다.
2. 줄어든 게 맞고 **의도한 것이라면**(중복 대량 정리 등) 다시 돌리되
   `node scripts/verify-backup.mjs --allow-shrink`로 한 번 통과시킨다.
3. 의도한 게 아니라면 DB를 먼저 본다. 백업은 건드리지 않는다.
4. 수동 덤프: `node scripts/dump-content.mjs` 후 `git add songs movies` →
   커밋. `git add -A`는 쓰지 않는다(다른 작업 파일이 섞인다).
5. 최근 태그 확인: `git tag --list 'db-backup-*' | tail -5`

## 5. 환경변수를 넣었는데 적용이 안 된다

**증상** 값을 분명히 넣었는데 "설정되지 않음"으로 동작한다.

**원인** 붙여넣기에 **BOM(U+FEFF)이나 앞뒤 공백, 감싼 따옴표**가 섞였다.
2026-08월에 `LYRA_CONTENT_STORE`와 `DATABASE_URL`이 이것 때문에 **이틀간 조용히
죽어** 있었다.

**대응** 값을 지우고 따옴표 없이 다시 입력한다. PowerShell로 파일을 만들었다면
`Out-File`이 기본으로 BOM을 붙인다 — `-Encoding utf8`을 명시한다.

**현재 정규화되는 것** `DATABASE_URL`·`LYRA_CONTENT_STORE`(content-db.js),
`GEMINI_API_KEY`(gemini.js), `NEON_API_KEY`(usage-metrics.js),
`TMDB_API_KEY`(tmdb.js). 새 환경변수를 추가하면 같은 함정을 의심하고
`clean()`을 통과시킨다.

## 6. 배포가 안 된다

GitHub 계정이 abuse 오탐으로 플래그된 상태다(티켓 #4667653). Vercel Git 연동이
익명 접근에 의존하기 때문에 **대시보드 Redeploy 버튼은 새 커밋을 절대 반영하지
않는다** — 같은 커밋만 다시 빌드한다.

배포는 CLI 업로드로: `pnpm deploy:prod`. 깨끗한 detached worktree에서만
올린다 — 로컬 폴더를 직접 올리면 미추적 파일이 섞인다.

해제 확인:
```bash
curl -s -o /dev/null -w '%{http_code}' https://github.com/bluehhhh-byte   # 200이면 해제
curl -s -o /dev/null -w '%{http_code}' https://github.com/torvalds        # 대조군
```

## 넘지 말 것

- 유료 전환으로 해결하지 않는다.
- 캐시 시한을 줄이지 않는다(§1).
- Gemini 5xx를 재시도하지 않는다(§2).
- 콘텐츠 저장이 GitHub 커밋을 만들게 하지 않는다 — 그게 계정 플래그의 직접
  원인이었다(11분 1,059커밋).
