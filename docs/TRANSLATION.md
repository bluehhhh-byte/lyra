# 번역 규칙

가사에 번역을 붙일 때 지키는 것들. 이미 지켜 온 관행인데 적혀 있지 않아서, 사람이 바뀌거나
시간이 지나면 흔들릴 자리를 문서로 못 박는다.

원문을 다루는 대원칙은 [`docs/PROJECT.md`](PROJECT.md)에, 일괄 작업 절차는
[`docs/AI-BULK-WORKFLOW.md`](AI-BULK-WORKFLOW.md)에 있다.

---

## 1. 방향 — 어느 쪽으로 옮기는가

한 곡 안에 두 종류의 줄이 섞여 있고, 각각 반대 방향의 번역을 기다린다.

| 원문 줄 | 붙이는 번역 | 판정 |
|---|---|---|
| 영어·일본어 줄 | 한국어 | `needsKo()` |
| 한국 곡의 한국어 줄 | 영어 | `needsEn()` |

곡의 `lang`이 아니라 **그 줄에 무엇이 적혀 있는지**로 판단한다. `lang: ko`인 곡에도 영어로만
된 줄이 많고, 그 줄에는 한국어 번역이 필요하다. 반대로 한국어 줄에는 영어 번역이 붙는다.

외국곡 속의 한국어 줄은 대개 이미 번역이므로 대상이 아니다.
한국어 가사가 3줄도 안 되는 곡은 영어 번역 대기열에 올리지 않는다 — 영어곡에 한 줄 섞인
정도까지 세면 대기열이 의미를 잃는다.

### 한 줄 안에 언어가 섞였으면 — 조각별로 교차한다

주 언어를 골라 줄 전체를 한쪽으로 옮기지 않는다. **한국어 조각은 영어로, 영어·일본어 조각은
한국어로** 각각 뒤집어 한 줄로 쓴다.

| 원문 | 옳음 | 틀림 |
|---|---|---|
| `가슴 안에 가득 차 커져가는 innocent` | `순수, filling up inside my chest and growing larger` | `The innocence filling my chest and growing` |
| `All I can do is try, 우리만에 시간` | `내가 할 수 있는 건 노력뿐, the time that was only ours` | `All I can do is try—the time that was only ours` |
| `먼저 말하고 싶은 내 goodbye, 길을 잃어` | `My 작별 that I want to say first, I've lost my way` | `My goodbye that I want to say first, I've lost my way` |

'틀림' 쪽의 공통점은 **독자가 원래 못 읽던 절반이 그대로 남는다**는 것이다. 주 언어로 줄
전체를 옮기면 영어 조각은 영어 결과물 안에 그대로 얹히고, 번역이 붙었는데도 그 부분만
읽히지 않는다. 교차하면 모든 조각이 반대편 언어로 도착한다.

한국어 문장 속에 박힌 외래어 한 낱말도 뒤집는다. 영어 결과물 안에 그냥 두면 자연스럽게
읽히기 때문에 모델이 가장 자주 빠뜨리는 자리다 — 위 표의 `goodbye` → `작별`이 그 경우다.

> 규칙이 사는 곳은 두 군데다: `lib/admin/song-meta.js`(새 곡 번역)와
> `app/api/admin/songs.js`(빠진 번역 보충). 한쪽만 고치면 경로에 따라 결과가 갈린다.

### 방향은 줄마다 하나뿐이다

`needsKo`와 `needsEn`은 따로 판단하지 않는다. `translationTarget()` 하나가 방향을 정하고,
두 판정은 그 답을 읽는다. 한영이 섞인 줄에서는 **우세한 언어**가 방향을 정한다 —
`불을 붙여 brand new`는 한국어가 주라 영어로 옮긴다.

둘 다 참이 되게 두면 안 된다. 번역 칸은 줄마다 하나뿐이라, 어느 방향으로 채우든 그 줄이
"끝난 줄"이 되기 때문이다. 그 틈으로 한국어→한국어 재작성이 들어왔다 —
아이유 <Dear my crazy soulmate>의 `다 잊어버려` → `전부 잊어버려`, 코퍼스에 316줄.

### 칸이 찼다고 번역된 것이 아니다

`translationFilled()`가 칸의 **언어**를 본다. 다만 두 방향은 대칭이 아니다:

| 방향 | 칸에 무엇이 | 판정 |
|---|---|---|
| → 영어 | 한국어가 들어 있다 | 번역이 아니다. 다시 해야 한다 |
| → 한국어 | 라틴 문자가 들어 있다 | 맞을 수 있다. 건드리지 않는다 |

한국어 방향에 같은 검사를 걸면 `Bk, Bk, Bk` → `Bk, Bk, Bk` 같은 추임새 268줄이 대기열에
올라온다(966곡 29,810줄 실측). 추임새·고유명사·굳이 옮기지 않기로 한 후렴은 라틴 그대로가
답이고, 그건 사람이 이미 내린 결정이다.

### `lang`이 틀려도 곡을 가리지 못한다

`effectiveLang()`이 선언이 아니라 가사를 본다 — 한국어 원문이 3줄 이상이면 한국 곡이다.
아이유 곡은 가사 44줄 중 27줄이 한국어인데 `lang: en`으로 등록돼 있었고, `needsEn`이
`lang === "ko"`만 보던 시절 그 한 글자가 곡 전체를 검사 밖에 두었다.

`frontmatter`의 `lang` 자체를 고칠 때는 기준이 하나 더 붙는다 — 가사가 한국어인 것과
사람이 넣은 메타데이터(`tags`의 `한국`·`K-Pop`, 한글 아티스트명)가 **둘 다** 맞아야 한다
(`metadataSaysKorean()`). 원문 칸에 한국어 번역이 잘못 들어간 외국곡이 가사만 보면
똑같이 생겼기 때문이다. `scripts/fix-song-lang.mjs`가 이 규칙으로 고치고, 근거가 하나뿐인
곡은 손대지 않고 남긴다.

## 2. 비우지 않는다

**애드리브도 옮긴다.** `Oh` `Yeah` `Woo` 같은 감탄사는 뜻이 없어 보여도 화면에는 영어로
남는다. 조용히 건너뛰면 번역이 있는 줄과 없는 줄이 섞여 읽기가 끊긴다.

**고유명사는 음역한다.** `Ryudejakeiru` → `류데자케이루`, `1LLIONAIRE` → `일리네어`.
사람·팀·지명은 한국에서 통용되는 표기를 쓴다.

**욕설과 거친 표현은 순화하지 않는다.** 원문의 세기를 그대로 옮긴다. 가사의 태도를 지우는
것도 훼손이다.

**의미가 흐린 줄도 비워 두지 않는다.** 무슨 뜻인지 확신이 없으면 가장 그럴듯한 해석을 적고
넘어간다. 빈칸보다 낫다.

---

## 3. 반복은 같게

같은 원문 줄에는 같은 번역이 들어간다. `scripts/apply-translations.mjs`가 원문 텍스트를
키로 쓰기 때문에 곡 안에서 자동으로 같아진다.

후렴이 절마다 다르게 번역되면 같은 노래로 읽히지 않는다. 문맥 때문에 일부러 다르게 하고
싶으면 그 줄만 손으로 고치고 이유를 남긴다.

> 같은 원문에 다른 번역이 붙은 구절은 `pnpm lint:data`가 경고로 알려준다.
> 곡 사이의 차이(다른 곡의 같은 가사)는 문제가 아니다.

---

## 4. 번역하지 않는 것

가사가 아닌 줄에는 번역을 붙이지 않는다. `lib/admin/needs.js`의 `isNonLyricLine()`이
가려낸다.

- **화자 표시** — `(Michael):` `(Both):`
- **캡션에 같이 적어 둔 관련곡 목록** — `2. Sonic Youth - Stones (2004)`
- **숫자 카운트** — `1, 2, 3, 4`
- **해설 문단** — 60자가 넘고 한국어가 주가 되는 줄. 곡 설명·감상문·시나리오 인용이다.
  영어를 인용하고 있어도 번역 대상이 아니다.
- **본인 해설** — `🗨` `✏`로 시작하는 줄
- **연 메모** — `//`로 시작하는 줄

연주곡(`instrumental: true`)과 원문 비공개 곡(`lyrics_none: true`)의 본문은 해설이므로
통째로 제외된다.

---

## 5. 원문은 건드리지 않는다

번역은 `> ` 줄로 원문 **아래에** 끼워 넣는다. 원문 줄의 글자는 한 자도 바뀌지 않는다.
`source_hash`는 계속 인스타그램 원본을 가리키고, `pnpm verify:instagram`이 매번 대조한다.

diff에 삭제된 가사 줄이 있으면 무언가 잘못된 것이다. 번역 작업의 diff는 순수 추가여야 한다.

원문 자체의 오타를 공식 가사로 바로잡아야 할 때는 번역이 아니라 **교정** 절차를 쓴다 —
줄마다 사유와 근거 URL을 `data/lyrics-corrections.json`에 남기고, 검증기가 근거 있는
차이만 통과시킨다.

---

## 6. 보이지 않는 글자를 조심한다

인스타그램 캡션에는 눈에 보이지 않는 문자가 섞여 들어온다. 저장소에 실제로 있는 것들:

| 문자 | 정체 | 개수 |
|---|---|---|
| `U+00A0` | 줄바꿈 없는 공백 | 539 |
| `U+2028` | 줄 구분자 | 331 |
| `U+3000` | 전각 공백 | 136 |
| `U+2005` | 4분의1 em 공백 | 13 |

`apply-translations.mjs`의 `norm()`이 공백류를 전부 보통 공백으로 눕혀서 대조한다.
이 처리가 없던 시절에는 원문에 분명히 있는 줄이 "원문을 못 찾음"으로 남았고, 번역이 조용히
누락됐다. 대조 로직을 건드릴 때 이 정규화를 빼지 않는다.

## 7. 작업 흐름

```
node scripts/needs-work.mjs          진단 — 무엇이 비어 있는지
  → 배치로 원문 줄만 뽑는다 (곡별 고유 줄, 130~170줄)
  → 번역을 { "slug": { "map": { "원문": "번역" } } } 형태로 쓴다
node scripts/apply-translations.mjs <파일>   반영 — `> ` 줄만 끼워 넣는다
pnpm test && pnpm lint:data          검증
pnpm verify:instagram <내보내기 폴더>  원본 대조
```

`apply-translations`는 이미 번역이 붙은 줄을 건너뛰므로 같은 파일을 여러 번 적용해도
덧쓰지 않는다. "원문을 못 찾은 항목"이 0이 아니면 키가 원문과 다르다는 뜻이니,
공백·따옴표·줄바꿈을 의심한다.

## 한영 혼용 줄 — 한글은 그대로, 영어만 옮긴다

한 줄에 한글과 외국어가 섞여 있으면, **한글 부분은 원문 그대로 두고 외국어 부분만
옮긴다.** 매끄럽게 다듬는다며 한글까지 다시 쓰면 원문이 사라진다 — 그 줄을 읽는
사람은 무엇이 가수가 쓴 말이고 무엇이 우리가 붙인 말인지 구별할 수 없다.

```
원문   유행이라지 마 Been there done it
맞음   > 유행이라지 마 다 해봤어          한글 그대로, 영어만 옮김
틀림   > 트렌드라 말하지 마, 우린 이미 다 겪어봤으니   한글까지 다시 씀
```

한글만 있는 줄에는 한국어 번역을 붙이지 않는다. 옮길 것이 없다.
(한국 곡의 한국어 줄에 붙이는 **영어** 번역은 방향이 반대이므로 이 규칙과 무관하다.)

예외는 두 가지뿐이다:
- **맞춤법·표기 교정** — `앰버서더 → 앰배서더`처럼 틀린 표기를 바로잡는 경우
- **한국어로 성립하지 않는 경우** — 조사가 외국어 서술어에 걸려 있어 그대로 두면
  문장이 되지 않을 때(`난 그대가 忘れない` → `난 그대를 잊지 않아`)

### 고칠 때

```bash
node scripts/retranslate.mjs <file.json> --check   # 무엇이 바뀌는지만 본다
node scripts/retranslate.mjs <file.json>           # 교체한다
```

`apply-translations.mjs`는 비어 있는 줄에만 붙인다. 이미 붙어 있는 번역을 고치는
것은 `retranslate.mjs`다. 둘 다 원문 줄은 건드리지 않는다.
