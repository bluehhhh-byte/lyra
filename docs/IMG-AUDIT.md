# 원본 `<img>` 감사

2026-08-27 `node scripts/audit-images.mjs --check`로 JSX를 다시 측정했다. 주석을 제외한 실제 `<img>`는 **18개 파일, 25곳**이다. 이전 개선안에 적힌 17곳보다 8곳 늘어난 값이며, 새 관리자 미리보기와 발행 후보 화면까지 포함한 현재 기준이다.

| 구분 | 수 | 판단 |
| --- | ---: | --- |
| Canvas에서 생성한 `blob:` 카드 미리보기 | 5 | `next/image` 최적화 대상이 아니다. 브라우저가 방금 만든 원본을 즉시 검수해야 한다. |
| 오류 시 숨김을 제공하는 `CoverImage` 내부 | 1 | 동적 외부 URL과 실패 처리를 캡슐화한 의도적 원본 태그다. |
| 음원 artwork·TMDB 포스터·기록 이미지 등 런타임 외부 URL | 19 | 호스트가 데이터마다 달라 빌드 시 크기/도메인을 확정할 수 없다. 작은 관리자 썸네일은 `loading=lazy` 또는 제한된 크기로 표시하고, 카드 Canvas용 TMDB 원본만 `/api/img` 프록시를 쓴다. |
| 합계 | **25** | 정적 로컬 이미지가 없어 이번 감사에서 `next/image`로 바꿀 가치가 확인된 곳은 0곳이다. |

모든 태그를 기계적으로 바꾸지 않는다. 새 원본 태그가 생기면 검사 실패가 그 위치를 보여 주며, 이 표에 목적과 최적화 여부를 먼저 기록해야 한다. 정적 로컬 자산이나 고정 크기의 공개 핵심 이미지가 추가되면 그 사용처부터 `next/image` 전환을 검토한다.
